## 0.1.0

### Minor Changes

- [#4](https://github.com/softistx/nxgt-di/pull/4) [`af19b45`](https://github.com/softistx/nxgt-di/commit/af19b453a5d0af08ead89809b68ae44619ca379c) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Add Modules, overrides and `init`. `defineModule<Requirements>()(build)` declares a reusable group of Providers that states what it needs, one map each (`singletons`, `scoped`, `slots`), and `container.use(module)` adds it; a missing requirement, one with another value type, a singleton requirement met only by a scoped entry, or a name the Container already has fails to compile with a message naming the gap. `container.override(token, value)` returns a new Container in which `token` gives `value`, whatever its lifetime; the original is unchanged, the two share no created value, and the value is not disposed by the Container, since the caller owns it. A Slot cannot be overridden: give its fake to `createScope` (at runtime, `SlotOverrideError`, code `DI_SLOT_OVERRIDE`). `await container.init()` creates every singleton in provide order and rejects with the first failing factory's error; what failed is not cached, so a later resolve retries. `use` checks at runtime that a Module's `build` returned the Container it was handed, with Providers added, and throws `ModuleEscapedError` (`DI_MODULE_ESCAPED`) otherwise. `init()` on a disposed Container rejects with `ContainerDisposedError`.

- [#1](https://github.com/softistx/nxgt-di/pull/1) [`f044f08`](https://github.com/softistx/nxgt-di/commit/f044f08623dd447368b557fa16b5388c4fa67b18) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Wire services with typed Tokens: `token<T>()(name)` creates one, and `container().provide(token, factory, { lifetime, dispose })` adds a Provider whose factory sees only the Tokens provided before it, so a missing dependency, a cycle or a duplicate Token name fails to compile. `resolve` and `get` always return a Promise. Singletons are created once per Container, transients on every resolve, and `await using` (or `[Symbol.asyncDispose]()`) disposes of every created value in reverse creation order, transients included, falling back to the value's own `Symbol.asyncDispose` or `Symbol.dispose`. Errors carry stable codes: `DI_TOKEN_NOT_PROVIDED`, `DI_DUPLICATE_TOKEN_NAME`, `DI_CONTAINER_DISPOSED` and `DI_DISPOSE_FAILED`. A Token's name must be exactly one string literal: a name widened to `string`, a template pattern or a union is refused by `token()` and by `provide`. `resolve` and `get` take one Token at a time, so a union of Tokens fails to compile. `AnyToken`, the type every Token is assignable to, is exported for helpers that accept any Token.

- [#5](https://github.com/softistx/nxgt-di/pull/5) [`e2ad953`](https://github.com/softistx/nxgt-di/commit/e2ad9538eb513d4c6668e2f1924d4a0e02fca080) Thanks [@SteveGT96](https://github.com/SteveGT96)! - First public release. The README is now the npm page: Install (the `typescript` peer, bundler resolution, `strict: true`), one example for each area, a table of every export and a table of every error code, with links to the guides (Tokens and Providers, Scopes and Slots, Modules, Testing, Lifecycle) and to troubleshooting.

- [#3](https://github.com/softistx/nxgt-di/pull/3) [`e46b587`](https://github.com/softistx/nxgt-di/commit/e46b58734d8ebe81978a2f8d0b35e6ccfb3393bd) Thanks [@SteveGT96](https://github.com/SteveGT96)! - Add Scopes and Slots. `lifetime: 'scoped'` makes one value per Scope, and `container.createScope(slots)` creates a Scope: `AsyncDisposable`, resolving everything its Container provides, sharing the singletons, and disposing of only what it made (its scoped values and the transients it resolved) in reverse creation order. `.slot(token)` declares a value that comes from outside, such as the request's principal; `createScope` must be given exactly the declared Slots, keyed by Token name, or it fails to compile. A Captive dependency now fails to compile: a singleton's factory cannot `get` a scoped Token or a Slot ("Token 'x' is scoped, captured by a singleton"), and the Container's own `resolve` takes singletons only. A transient declares `bound: 'singleton' | 'scoped'` (default `'singleton'`), the longest lifetime that may capture it. Disposing of the Container does not dispose of its live Scopes. New errors: `ScopeDisposedError` (`DI_SCOPE_DISPOSED`), `ScopeRequiredError` (`DI_SCOPE_REQUIRED`) and `MissingSlotError` (`DI_SLOT_MISSING`). `Container` now takes three type parameters, `Container<Singletons, Scoped, Slots>`; `Container<{ db: Db }>` still means a Container of singletons only. A factory typed apart as `Factory<Singletons, Scoped, T>` fits any Container that provides at least what it uses, and a factory typed to see more than its Provider is given (a scoped Token from a singleton, a later Token) is refused. `options` may be left out only for a singleton. `createScope` on a disposed Container throws `ContainerDisposedError`. `lifetime: undefined` means singleton. `DiError.token` is now `string | undefined`; it stays `string` on every subclass except `ContainerDisposedError`, whose `token` is `undefined` when `createScope` was called.
